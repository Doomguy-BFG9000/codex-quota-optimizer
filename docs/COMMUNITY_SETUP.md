# Repository community settings

The repository's files and GitHub feature settings are separate. This checklist records the intended setup; it does not claim these settings have been applied.

## Topics

On the repository homepage, open the About gear and add relevant topics:

```text
openai-codex
codex-cli
agent-skills
quota-management
developer-tools
token-optimization
```

These describe the audience and problem area. `token-optimization` is a discovery category, not a measured savings claim.

## Issues and Discussions

Under Settings > General > Features, keep Issues enabled and enable Discussions if desired. Issues are for reproducible bugs, actionable suggestions, and contribution tasks. Use Discussions for open-ended questions, design feedback, and shared experiences when available. Until Discussions is enabled, the question/suggestion issue form can collect that feedback.

The repository now has bug, suggestion, and testing-feedback issue forms plus a pull-request template. Two starter issues are labeled `good first issue`; the measurement request is labeled `help wanted`.

- [Windows PowerShell guide](https://github.com/Thlookingatyou/codex-quota-optimizer/issues/2)
- [Synthetic alias fixtures](https://github.com/Thlookingatyou/codex-quota-optimizer/issues/3)
- [Paired quota measurement](https://github.com/Thlookingatyou/codex-quota-optimizer/issues/4)

## First feedback to seek

Ask testers whether they can install/run the tool, whether their client writes usable local observations, whether missing telemetry is explained clearly, and which recommendation is confusing. Invite a small redacted reproduction for bugs. Do not request full private logs, credentials, stars, or unsupported claims of savings.

Real consumption results should follow [the benchmark protocol](BENCHMARK.md). The first announcement can honestly ask people to test behavior before any measured savings result exists.
